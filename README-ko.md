# Laya RAG 판별기 (한국어판)

브라우저 안에서만 동작하는 RAG 주장 검증 파이프라인의 한국어판입니다. 검색어(주장)는 코퍼스에서 검색되고, **Laya typed-decisions 모델**이 검색된 근거가 주장을 지지하는지 판정합니다: *지지함 / 지지하지 않음* + 확률 + 신뢰도 게이트. 청킹, 임베딩, 벡터 스토어, 검색, 판정이 전부 브라우저 탭 안에서 이루어지며 서버·API 키·비용이 없고, 주장 텍스트는 페이지 밖으로 나가지 않습니다.

원본(영어판): https://github.com/vishalmysore/layaAsRagJudge · 이 한국어판의 변경 사항은 아래 "한국어화" 절 참조.

페이지 3개:

- **주장 검증** (`index.html`): 주장 하나가 파이프라인 전체를 통과하는 과정을 단계별로 보여줍니다 — 검색된 구절과 코사인 점수, Laya에 보낸 정확한 질문과 상태, 확률, 자동/차단/보류 게이트, 검색된 구절이 강조된 원본 문서.
- **평가** (`rag-eval.html`): 라벨이 붙은 72개 주장 전체를 파이프라인으로 실행해 골드 라벨과 비교합니다. 정확도, 균형 정확도, 오검증률, AUROC, 근거 회수율@k, 신뢰도 대 커버리지 표, 데이터셋/주장 유형별 분석, 중위/p95 지연 시간. 슬라이더를 옮기면 모델 호출 없이 저장된 결과를 다시 채점합니다.
- **라우터** (`router.html`): RAG 라우터. Laya가 질문을 어느 지식 베이스(백과사전/뉴스/정책 RAG)로 보낼지, 검색 없이 답할지 결정합니다. 선택된 지식 베이스 안에서 검색하고, 두 번째 Laya 질문이 그 구절이 실제 답인지 확인합니다.

## 파이프라인

```
corpus.json ──► 문장인식 청킹 (청크당 2문장)
            ──► paraphrase-multilingual-MiniLM-L12-v2 임베딩 (384-d)
            ──► IndexedDB "passages" 스토어
주장 ──► 같은 임베더 ──► brute-force 코사인 top-k (k = 3)
     ──► Laya typed 질문 { claim, evidence: [top-k 구절] } ──► p(지지)
     ──► 판정 (p ≥ 컷오프) ──► 게이트: 자동(지지 확신) / 차단(미지지 확신) / 보류(사람 검토)
```

| 구성 | 파일 | 메모 |
|---|---|---|
| 청킹·코사인·top-k | `web/rag.js` | 순수 함수, Node 단위 테스트 |
| 임베더 | `web/embedder.js` | `Xenova/paraphrase-multilingual-MiniLM-L12-v2` int8 ONNX (다국어, 한국어 포함) |
| 벡터 스토어 | `web/store.js` | IndexedDB: `passages` / `claims` / `runs` / `meta`. 차단되면 메모리 폴백 |
| 판별기 | `web/judge.js`, `web/laya-core.js`, `web/model.js` | 주장당 typed 질문 1개 |
| 지표 | `web/metrics.js` | 정확도, 균형 정확도, 오검증률, AUROC, 커버리지, 지연 퍼센타일 |
| 접착제 | `web/pipeline.js` | index → retrieve → judge, run 키, 녹음 압축 |

## 한국어화 (이 포크의 변경 사항)

1. **판별 모델**: 영어 체크포인트(`VishalMysore/layaForWebTrained`, ModernBERT, int8 422MB) 대신 **`convaiinnovations/laya-multilingual`**(mmBERT, 다국어, int8 442MB)의 ONNX 변환본을 사용합니다. `web/model.js`의 기본 베이스가 이를 가리키고, `web/laya-core.js`의 특수 토큰 감지(`specialIds`)는 토크나이저 설정(`<bos>/<eos>/<pad>/<mask>` 등)을 기준으로 자동 감지합니다. ONNX 변환·호스팅은 https://realizer-1966.github.io/laya-web-ko/model-multilingual/ 에서 같은 도메인 정책으로 제공됩니다.
2. **임베더**: 영어 단독인 `all-MiniLM-L6-v2` 대신 다국어 `Xenova/paraphrase-multilingual-MiniLM-L12-v2`(int8, 최대 입력 128 토큰). 청크가 한국어 기준으로 128 토큰을 넘으면 뒤가 잘립니다.
3. **문장 분리**(`web/rag.js`): 영어의 "대문자로 시작하는 다음 문장" 가정을 제거해 한국어 문장 경계(마침표/물음표/느낌표 + 공백)를 인식합니다.
4. **코퍼스·질문·UI**: `web/corpus.json`(18개 가상 문서 + 36:36 균형의 72개 주장), `web/router.json`(32개 라우팅 질문)과 세 페이지의 UI·상태 메시지를 한국어로 작성했습니다. 고유명사는 음역(바른홀트 등대, 소렐 밸리 철도, 헬레나 카스텔란, 루멘 홈 등)하여 전체에서 일관되게 사용합니다.
5. **판정 질문 프리셋**(`web/judge.js`): 한국어 지문 + 서술형 선택지(two-options / three-options / yes-no). 언어 불일치는 오분류를 유발하므로 질문·선택지·근거 문장의 언어를 일치시키는 것이 이 체크포인트에서 중요합니다(영어판에서 측정된 교훈).
6. `web/recorded.json` / `web/router-recorded.json`은 같은 모델로 **한국어 코퍼스에서 다시 녹음**한 값입니다. 질문 지문이 바뀌면 run 키의 지문 지문(fingerprint)이 바뀌므로 다시 녹음해야 합니다.

## 성능 (한국어 샘플, convaiinnovations/laya-multilingual, int8 WASM, 72주장) — 실측 2026-11-05

| 판별 질문 | 검색 범위 | 정확도 | 균형 정확도 | 오검증률(FVR) | AUROC | 근거 회수율@3 |
|---|---|---|---|---|---|---|
| 두 선택지 (기본) | 주장의 문서 | **62.5%** | 62.5% | 36.1% | 0.62 | **93%** |
| 두 선택지 | 전체 코퍼스 | 61.1% | 61.1% | 33.3% | 0.65 | 88% |
| 세 선택지 (지지/반박/언급없음) | 주장의 문서 | 58.3% | 58.3% | **11.1%** | 0.60 | 93% |
| 예/아니오 | 주장의 문서 | **65.3%** | 65.3% | 19.4% | **0.67** | 93% |

- 판별 지연 중위 ≈ 2.6초 (WASM 4스레드; 백그라운드 탭에서는 크게 늘어난다).
- 주장 유형별(두 선택지, 컷오프 0.5): 숫자 0.80, 검증 불가 0.80, 개체 0.50, 모순 0.59, 추론 0.50, 바꿔 말함 0.65. 세 선택지에서는 모순 0.95, 개체 0.75지만 바꿔 말함 0.35.
- 신뢰도 0.10 게이트: 78% 자동 처리(정확도 유지). 이 체크포인트의 확률이 압축되어 있어 영어판처럼 0.10에서 정확도가 크게 오르지는 않는다.

영어판(75.0%, AUROC 0.80)보다 전반적으로 낮다. 다국어 체크포인트는 이 판별 작업 자체는 한국어에서도 동작하지만(우연 수준 0.50 대비), 특히 지지 주장(바꿔 말함·추론)을 놓치는 경향이 강하다.

### 라우터 성능 — 실측 (32질문)

| 항목 | 영어판 (README) | 한국어판 실측 |
|---|---|---|
| 최종 결과 일치 | 94% | **28%** |
| 지식 베이스 선택(상위 3개 중) | 96% | 46% |
| 옳은 지식 베이스 검색 | 100% | 21% |
| 지식 질문을 잘못 건너뜀 | 0 | 17 |
| 답변 확인(답변됨 여부) | 96% | 50% |
| 근거 회수율@3 | 100% | 89% |

**라우터는 이 체크포인트에서 한국어로 동작하지 않는 수준이다.** 지식 질문의 p(검색 없음)가 0.6–1.0으로 부풀고, 백과사전/뉴스/정책 구분도 랜덤 수준이며, 답변 확인 절반이 답이 있는 구절을 답 없다고 판정한다. 슬라이더를 조정해도 35%를 넘지 못한다(같은 32질문에 맞춘 값이라 과대평가). 이 페이지는 개념 데모로 남겨두고, 실제 용도에는 영어판 체크포인트나 이 작업에 특화된 파인튜닝이 필요하다.

## 샘플 코퍼스

`web/corpus.json`은 세 장르(백과사전/뉴스/정책·문서)의 가상 문서 18개와 주장 72개(문서당 4개, 지지 36 / 미지지 36)입니다. 각 주장은 유형이 붙습니다: *바꿔 말함(paraphrase)*, *추론(inference)*, *숫자(number)*, *개체(entity)*, *모순(contradiction)*, *검증 불가(unverifiable)*. 모든 문서는 이 데모를 위해 **가상으로 작성**되었으므로 주장의 골드 라벨은 문서(근거)에만 의존하고 세계 지식에는 의존하지 않습니다.

## 로컬 실행

```bash
npm ci && npm test
node scripts/prepare_site.mjs
python serve.py 8769
```

http://localhost:8769 를 엽니다. `serve.py`는 ONNX Runtime의 멀티 WASM 스레드를 위해 COOP/COEP 헤더를 보냅니다.

첫 모델 로드는 Laya(int8 442MB)와 임베더(int8, 다국어 MiniLM)를 내려받고 둘 다 캐시됩니다. 이후에는 코퍼스, 구절 벡터, 실행 결과가 IndexedDB에 있어 오프라인으로도 동작합니다.

## recorded.json 다시 녹음

코퍼스나 판정 질문 지문을 바꾸면 `recorded.json` 단위 테스트가 실패합니다(run 키에 지문 fingerprint 포함). 평가 페이지에서 모델을 로드하고 각 설정(두/세 선택지, 예/아니오, 문서/전체 코퍼스)을 실행한 뒤 콘솔에서 `JSON.stringify(__lrj.recorded())` 결과를 `web/recorded.json`에 저장하세요. 구절·주장 텍스트는 파일에서 제외되고 로드 시점에 코퍼스로부터 재구성됩니다.

## 배포

`.github/workflows/deploy.yml`이 단위 테스트를 실행하고 `dist/`(페이지 + 벤더링된 ONNX Runtime Web, Tokenizers.js — 약 30MB)를 GitHub Pages에 배포합니다. 모델은 번들에 포함되지 않고 런타임에 스트리밍됩니다.
