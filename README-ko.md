# Laya RAG 판별기 (한국어판)

브라우저 안에서만 동작하는 RAG 주장 검증 파이프라인의 한국어판입니다. 검색어(주장)는 코퍼스에서 검색되고, **Laya typed-decisions 모델**이 검색된 근거가 주장을 지지하는지 판정합니다: *지지함 / 지지하지 않음* + 확률 + 신뢰도 게이트. 청킹, 임베딩, 벡터 스토어, 검색, 판정이 전부 브라우저 탭 안에서 이루어지며 서버·API 키·비용이 없고, 주장 텍스트는 페이지 밖으로 나가지 않습니다.

원본(영어판): https://github.com/vishalmysore/layaAsRagJudge · 이 한국어판의 변경 사항은 아래 "한국어화" 절 참조.

페이지 3개:

- **주장 검증** (`index.html`): 주장 하나가 파이프라인 전체를 통과하는 과정을 단계별로 보여줍니다 — 검색된 구절과 코사인 점수, Laya에 보낸 정확한 질문과 상태, 확률, 자동/차단/보류 게이트, 검색된 구절이 강조된 원본 문서.
- **평가** (`rag-eval.html`): 라벨이 붙은 72개 주장 전체를 파이프라인으로 실행해 골드 라벨과 비교합니다. 정확도, 균형 정확도, 오검증률, AUROC, 근거 회수율@k, 신뢰도 대 커버리지 표, 데이터셋/주장 유형별 분석, 중위/p95 지연 시간. 슬라이더를 옮기면 모델 호출 없이 저장된 결과를 다시 채점합니다.
- **라우터** (`router.html`): RAG 라우터. Laya가 질문을 어느 지식 베이스(백과사전/뉴스/정책 RAG)로 보낼지, 검색 없이 답할지 결정합니다. 선택된 지식 베이스 안에서 검색하고, 두 번째 Laya 질문이 그 구절이 실제 답인지 확인합니다.

## 파이프라인

```
corpus.json ──► 문장인식 청킹 (청크당 2문장)
            ──► paraphrase-multilingual-MiniLM-L12-v2 임베딩 (384-d)
            ──► IndexedDB "passages" 스토어
주장 ──► 같은 임베더 ──► brute-force 코사인 top-k (k = 3)
     ──► Laya typed 질문 { claim, evidence: [top-k 구절] } ──► p(지지)
     ──► 판정 (p ≥ 컷오프) ──► 게이트: 자동(지지 확신) / 차단(미지지 확신) / 보류(사람 검토)
```

| 구성 | 파일 | 메모 |
|---|---|---|
| 청킹·코사인·top-k | `web/rag.js` | 순수 함수, Node 단위 테스트 |
| 임베더 | `web/embedder.js` | `Xenova/paraphrase-multilingual-MiniLM-L12-v2` int8 ONNX (다국어, 한국어 포함) |
| 벡터 스토어 | `web/store.js` | IndexedDB: `passages` / `claims` / `runs` / `meta`. 차단되면 메모리 폴백 |
| 판별기 | `web/judge.js`, `web/laya-core.js`, `web/model.js` | 주장당 typed 질문 1개 |
| 지표 | `web/metrics.js` | 정확도, 균형 정확도, 오검증률, AUROC, 커버리지, 지연 퍼센타일 |
| 접착제 | `web/pipeline.js` | index → retrieve → judge, run 키, 녹음 압축 |

## 한국어화 (이 포크의 변경 사항)

1. **판별 모델**: 영어 체크포인트(`VishalMysore/layaForWebTrained`, ModernBERT, int8 422MB) 대신 **`convaiinnovations/laya-multilingual`**(mmBERT, 다국어, int8 442MB)의 ONNX 변환본을 사용합니다. `web/model.js`의 기본 베이스가 이를 가리키고, `web/laya-core.js`의 특수 토큰 감지(`specialIds`)는 토크나이저 설정(`<bos>/<eos>/<pad>/<mask>` 등)을 기준으로 자동 감지합니다. ONNX 변환·호스팅은 https://realizer-1966.github.io/laya-web-ko/model-multilingual/ 에서 같은 도메인 정책으로 제공됩니다.
2. **임베더**: 영어 단독인 `all-MiniLM-L6-v2` 대신 다국어 `Xenova/paraphrase-multilingual-MiniLM-L12-v2`(int8, 최대 입력 128 토큰). 청크가 한국어 기준으로 128 토큰을 넘으면 뒤가 잘립니다.
3. **문장 분리**(`web/rag.js`): 영어의 "대문자로 시작하는 다음 문장" 가정을 제거해 한국어 문장 경계(마침표/물음표/느낌표 + 공백)를 인식합니다.
4. **코퍼스·질문·UI**: `web/corpus.json`(18개 가상 문서 + 36:36 균형의 72개 주장), `web/router.json`(32개 라우팅 질문)과 세 페이지의 UI·상태 메시지를 한국어로 작성했습니다. 고유명사는 음역(바른홀트 등대, 소렐 밸리 철도, 헬레나 카스텔란, 루멘 홈 등)하여 전체에서 일관되게 사용합니다.
5. **판정 질문 프리셋**(`web/judge.js`): 한국어 지문 + 서술형 선택지(two-options / three-options / yes-no). 언어 불일치는 오분류를 유발하므로 질문·선택지·근거 문장의 언어를 일치시키는 것이 이 체크포인트에서 중요합니다(영어판에서 측정된 교훈).
6. `web/recorded.json` / `web/router-recorded.json`은 같은 모델로 **한국어 코퍼스에서 다시 녹음**한 값입니다. 질문 지문이 바뀌면 run 키의 지문 지문(fingerprint)이 바뀌므로 다시 녹음해야 합니다.

## 검색기 (advancedRagDemo 병합)

[advancedRagDemo](https://github.com/vishalmysore/advancedRagDemo)의 하이브리드 검색을 한국어 대응으로 이식한 것 (원본 코드는 영어 전용이라 한국어에서 BM25 점수가 항상 0이었다):

1. **한국어 인식 키워드 토크나이저** (`web/rag.js`의 `terms()`): 영어 단어·숫자는 통째로, 한글 run은 겹치는 문자 2-gram으로 분해한다. 공백 단위로 나누면 한국어를 토큰화할 수 없기 때문이다. "백과사전" → 백과/과사/사전.
2. **하이브리드 검색** (`hybridTopK`): 코사인과 BM25를 각각 min-max 정규화해 섞는다. 벡터 가중치 슬라이더(w)는 주장 검증·평가 두 페이지 모두에 있다. 라우터의 하이브리드 지식 베이스 검색도 같은 토크나이저를 공유한다.
3. **근접성 리랭킹** (`proximityScore`/`proximityRerank`): advancedRagDemo의 2단계 리랭커 포트 — 질의 키워드가 뭉쳐 있는 구절을 끌어올린다 (1차 점수 40% + 근접성 60%, 최소 토큰 윈도 스윕으로 계산).
4. **검색기 비교** (평가 페이지 사이드바): 골드 근거가 있는 주장 전체를 벡터 전용 / 키워드 전용 / 하이브리드 / 하이브리드+리랭킹 네 가지로 검색해 근거 회수율@k · 평균 골드 순위 · 지연을 비교한다. 판별기 호출이 전혀 없어 즉시 실행되며, 임베더만 필요하다.

기록된 실행 결과와의 호환은 유지된다: 코사인 기본값의 run 키는 그대로고, 하이브리드·리랭킹 설정은 키에 `ret:...` 접미사로만 붙는다 (`runKey`).

## 판별기 백엔드 Ⅱ — Ollama Clef

모델 카드의 "판별기 백엔드"에서 **브라우저 (Laya ONNX)** 대신 **Ollama (Clef)**를 고를 수 있다. Clef는 Cloudflare가 학습한 27B 멀티모달 판별 모델로, System One API를 그대로 말하므로 이 데모의 판별 흐름과 완벽히 호환된다.

### 실행 방법

```bash
ollama pull clef:cloud        # Ollama 0.40.6 이상 (클라우드 실행, 무료 로컬 설치 없음)
ollama pull clef:latest       # 또는 로컬 설치 (약 18–20 GB, 전송 없이 판별)
# 사이트를 열고 모델 카드에서 "Ollama (Clef)"를 선택 → 모델 태그 입력 → "모델 로드"
```

- 판별기만 Ollama로 교체된다. **검색기(다국어 MiniLM 임베딩·IndexedDB·한국어 BM25·근접 리랭킹)는 그대로 이 브라우저에서 실행**되므로 코퍼스와 벡터는 기기를 벗어나지 않는다.
- Clef는 질문마다 선택지 확률을 한 번의 추론으로 반환하고(`type: choice` → `probabilities`, `type: noul` → `noul`), `interpret()`·게이트·모든 지표 코드는 수정 없이 동작한다.
- 지연은 어댑터(`web/clef.js`)가 클라이언트 측에서 측정해 Laya의 `latency_ms` 필드와 동일하게 채운다. 토큰 시퀀스 뷰는 Clef에서는 비활성화되고 질문 JSON만 표시된다.

### 실측 (2026-11-09, clef:cloud, 코퍼스 6주장 스모크)

| 항목 | 브라우저 mmBERT (기록) | Ollama clef:cloud (실측) |
|---|---|---|
| 일치 | 6개 대상 62.5% 수준 | **6/6** |
| 신뢰도 | 압축됨 (게이트 0.10 필요) | **0.79–0.90** |
| 판별 지연 | ≈ 2.6 s (WASM) | **≈ 0.5–1.0 s** |
| 전송 | 없음 | 주장 + 근거 텍스트 |

### 주의사항

- **개인정보**: 브라우저 Laya는 어떤 텍스트도 페이지를 벗어나지 않지만, `clef:cloud`는 Ollama 서버 — 그리고 ollama.com 클라우드(유료 API, 입력 $0.24/1M 토큰)로 주장과 근거 텍스트를 전송한다. 모델 카드에 경고 배지가 표시된다. 전송을 원치 않으면 로컬 `clef:latest`를 쓰거나 브라우저 Laya를 유지한다.
- **CORS**: `localhost` 페이지에서는 기본 허용이다. GitHub Pages에서 실행하면 Ollama 서버 쪽에서 `OLLAMA_ORIGINS=https://<계정>.github.io` (또는 `*`)를 설정해야 한다.
- 서버 주소는 `?clefBase=http://다른호스트:11434` URL 파라미터로 바꿀 수 있다.
- 판별 결과 run 키의 variant가 `clef:cloud`로 따로 기록되므로, 기존 Laya 기반 `recorded.json` 실행 결과와 평가 페이지에서 공존·비교된다.

## 질의응답 (advancedRagDemo 병합, Phase 2)

4번째 페이지 (`chat.html`): 브라우저에서 끝나는 수집 → 검색 → 생성 → **답변의 문장별 판별**.

1. **문서 수집** (`web/ingest.js`): PDF(TXT/MD도) 파일을 브라우저에서 파싱(pdf.js, CMaps 포함 한국어 CID 폰트 대응), 청킹 → 다국어 MiniLM 임베딩 → IndexedDB에 업로드 전용 지식 베이스로 저장 (dataset `uploads`). 수집된 텍스트는 기기를 벗어나지 않는다. 내용 해시 docId로 같은 내용의 재업로드는 임베딩을 재사용한다.
   - 주의: advancedRagDemo의 텍스트 정규화는 인쇄 가능한 ASCII 외부 문자를 모두 지워 한글을 파괴하므로 재작성했다 (제어문자만 제거, 인쇄 가능한 유니코드는 유지). 회귀 테스트가 이를 감시한다.
2. **검색**: Phase 1의 하이브리드(코사인 + 한국어 BM25)로 근거 구절을 찾는다. 근거 범위는 업로드한 문서 / 예시 코퍼스.
3. **답변 생성** (`web/gen.js`): 각 문장이 [n] 인용을 갖도록 두 생성기를 제공한다 —
   - **Ollama 채팅 모델** (기본, 예: `glm-5.3-flash:cloud`) — 질문+근거가 Ollama 서버로 전송된다;
   - **Mock AI** (오프라인, 추출형) — 근거 문장을 그대로 인용해 모델·서버 호출이 전혀 없다.
4. **문장별 판별**: 답변을 문장으로 나누고(인용 분해 포함) 문장 하나하나를 판별기(브라우저 Laya 또는 Ollama Clef)에 넣어 "근거가 이 문장을 지지하는가?"를 묻는다 — 평가 페이지와 같은 질문·게이트·기준선. 자동/보류/차단으로 표시하고, 차단 문장이 있으면 배너로 경고한다. advancedRagDemo의 hallucination 배너(정규식 휴리스틱)를 실제 판별기로 대체한 부분이다.

### 주의사항

- 생성기가 Ollama 채팅 모델이면 질문과 근거가, 판별기가 `clef:cloud`면 답변 문장이 Ollama 서버(→ `:cloud`면 클라우드)로 전송된다. 전송 없이 전 과정을 보려면 생성기 = Mock AI + 판별기 = 브라우저 Laya 조합을 쓴다.
- pdf.js와 CMaps는 `dist/vendor/`에 함께 배포되어 오프라인 수집이 가능하다. 스캔본 PDF는 OCR이 필요하다.

## Lab 두 개 (advancedRagDemo 병합, Phase 3)

두 페이지 모두 모델 다운로드 없이 순수 계산만으로 동작하고, Node 단위 테스트(`tests/lab.test.mjs`)로 검증된다.

### 청킹 Lab (`lab.html`)
같은 문서·검색기(MiniBM25)·컨텍스트 예산에서 다섯 가지 청킹 전략을 **완전 근거 회수(complete-evidence recall)**로 비교한다:
고정 윈도 / 문장 윈도(rag.js와 같은 알고리즘) / 구조 인식(StrucChunk, arXiv 2610.26313) / QES 정확 DP와 겹침 탐욕(QESChunker, arXiv 2610.36557). 검색은 BM25 top-k 대비 **청크 그래프 + 개인화 PageRank**(SpectRAG-lite, arXiv 2610.36991)로 두 모드. 한국어화: 토크나이저를 rag.js의 문자 2-gram `terms()`로, 상호 참조 표기를 "Section x.y" → "x.y절"로. 기본 문서·질문은 이 저장소의 한국어 가상 규정(`policyCorpus.js`)이고, 자신의 마크다운 + 질문–근거 JSON을 붙여넣어도 된다. 뷰: 점수판 · 완전회수-대-예산 곡선(flat/graph) · 청크 경계 지도 · 질문 인스펙터.

### 프로덕션 Lab (`production.html`)
1일차 이후의 일: 벡터 인덱스를 계속 바뀌는 문서에 맞춰두는 9개 장애 모드를 결정적 시뮬레이션으로 각각 fix 없이/fix와 함께 재실행한다 (문서 ID, 콘텐츠 해시, 안정 청킹, 문서 버저닝, 원자적 전환, GC, 임베딩 버저닝, outbox·재조정, 버전 인식 캐시). 임베딩은 feature-hash 벡터(v1/v2 시드)라 두 "모델"의 벡터 공간이 실제로 호환되지 않는다 — 업그레이드 장애를 정확히 재현. **카오스 위크** 탭은 한 주의 사건(편집·크래시·배포·업그레이드·이벤트 소실·캐시 부패)을 켠 fix에 따라 채점해 등급(F~A)을 매긴다. 코퍼스는 이 저장소의 한국어 가상 "직원 규정" 1부 + 단문 KB 36개.

## 웹앱(PWA)

사이트는 설치형 웹앱입니다. Chrome/Edge/Samsung Internet에서 주소창 옆 설치 아이콘(또는 메뉴 → "앱 설치")로 홈 화면에 추가되고, 별창 없이 독립적으로 열립니다. `coi-sw.js`(기존 cross-origin isolation 서비스워커)가 앱 캐시를 겸한다: 문서는 network-first, 정적 자산은 stale-while-revalidate. 모델 파일은 model.js/embedder.js의 해시 키 Cache Storage, 벡터와 실행 결과는 IndexedDB — 첫 방문(모델 로드) 한 번 이후에는 오프라인으로도 검색·판별·게이트 전체가 동작한다(생성기 Mock AI 모드에서). 단축 아이콘: 질의응답/주장 검증/평가.

## 샘플 코퍼스

`web/corpus.json`은 세 장르(백과사전/뉴스/정책·문서)의 가상 문서 18개와 주장 72개(문서당 4개, 지지 36 / 미지지 36)입니다. 각 주장은 유형이 붙습니다: *바꿔 말함(paraphrase)*, *추론(inference)*, *숫자(number)*, *개체(entity)*, *모순(contradiction)*, *검증 불가(unverifiable)*. 모든 문서는 이 데모를 위해 **가상으로 작성**되었으므로 주장의 골드 라벨은 문서(근거)에만 의존하고 세계 지식에는 의존하지 않습니다.

## 로컬 실행

```bash
npm ci && npm test
node scripts/prepare_site.mjs
python serve.py 8769
```

http://localhost:8769 를 엽니다. `serve.py`는 ONNX Runtime의 멀티 WASM 스레드를 위해 COOP/COEP 헤더를 보냅니다.

첫 모델 로드는 Laya(int8 442MB)와 임베더(int8, 다국어 MiniLM)를 내려받고 둘 다 캐시됩니다. 이후에는 코퍼스, 구절 벡터, 실행 결과가 IndexedDB에 있어 오프라인으로도 동작합니다.

## recorded.json 다시 녹음
